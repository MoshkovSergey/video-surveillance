# Video Surveillance System

Система видеонаблюдения на базе:

- Go;
- React;
- TypeScript;
- PostgreSQL;
- Docker;
- FFmpeg / MediaMTX.

## Назначение

Система предназначена для:

- просмотра живого видео с камер;
- записи видеоархива;
- хранения и поиска записей;
- регистрации событий;
- интеграции с внешними системами безопасности, включая пожарную автоматику.

## Возможности

### Камеры и потоки

- Подключение камер по **RTSP** напрямую или через **ONVIF** (автополучение RTSP-адреса из профиля камеры).
- Опрос профилей ONVIF (основной/суб-поток) при добавлении и редактировании камеры.
- **Сетевой сканер камер** (ONVIF WS-Discovery, UDP-multicast 239.255.255.250:3702): поиск устройств в локальном сегменте, вывод имени, производителя, модели, адреса; быстрое добавление найденной камеры. Доступен только администратору.
- Трансляция через MediaMTX: HLS для веб-плеера, RTSP/WebRTC для внешних клиентов.
- Контроль доступности камер: мониторинг состояния путей MediaMTX, события «камера в сети» / «потеря связи», автоматический статус `error`.

### Запись и архив

- Непрерывная запись сегментами по **5 минут** (MediaMTX).
- Два режима записи на камеру: **непрерывная** и **по движению**.
- В режиме «по движению»: буфер из **3 последних сегментов** (~15 минут), ротация с удалением старых файлов.
- Точные клипы событий движения: **предзапись 5 с + постзапись 10 с**, вырезание FFmpeg (Docker-образ `jrottenberg/ffmpeg`, перекодирование в H.264 для совместимости с браузерами). Клипы хранятся в `storage/clips/` постоянно (`kept = true`).
- Архив с фильтрами по камере и дате, воспроизведение и скачивание через авторизованные запросы, метка «по движению» у клипов.

### Детекция движения

- Детекция по **событиям ONVIF** (PullPoint-подписка): камера сама сообщает о движении, сервер не декодирует видео.
- Эпизод движения: старт по первому событию, завершение после 10 секунд тишины.
- По эпизоду создаётся событие журнала и задача кадрирования клипа; клип готовится после закрытия покрывающего сегмента (не более ~5 минут).

### Монитор (видеостена)

- Сетки **6 / 9 / 12 / 15 / 18** ячеек (3×2 … 6×3).
- Назначение камер кликом из правой панели устройств; замена ячеек местами; освобождение ячейки.
- Сортировка списка камер: по имени, по статусу, по расположению; автозаполнение сетки.
- Раскладка сохраняется в `localStorage` и переживает навигацию и перезагрузку.
- В ячейке: имя камеры, индикатор статуса, подпись режима записи («по движению» / «непрерывно»).

### Журнал событий

- Типы событий: движение, камера в сети, потеря связи, пожарная тревога, обнаружение дыма, ручная тревога, ошибка записи.
- Фильтры по камере и типу, автообновление, колонка примечаний (длительность эпизода и т.п.).
- Для событий движения — кнопка **«Просмотр»**: модальный плеер проигрывает точный клип эпизода (при нескольких сегментах — последовательно).

### Пользователи и безопасность

- Аутентификация: JWT (access + refresh), хеширование паролей **argon2id**.
- Роли: `admin`, `operator`, `viewer`, `auditor` с разграничением на уровне API и интерфейса.
- Автоматическое создание первого администратора при пустой таблице пользователей.
- Раздел «Пользователи» (только администратор): список и создание учётных записей.

### Интерфейс

- React + TypeScript + Vite, тёмная тема в стиле web3 (glassmorphism, неоновые градиенты).
- Страницы: вход, камеры, монитор, архив, события, поиск камер, пользователи.
- Toast-уведомления (успех / ошибка / инфо), модальные окна, ролевая видимость элементов управления.

## Архитектура

```
IP-камера (RTSP/ONVIF)
        │ RTSP
        ▼
   MediaMTX (Docker)  ── HLS/WebRTC ──► веб-плеер
        │ запись сегментов (5 мин)
        ▼
 storage/recordings/cam_<uuid>/*.mp4
        │ сканер (30 c): синхронизация метаданных,
        │ ротация буфера, кадрирование клипов (FFmpeg)
        ▼
 storage/clips/cam_<uuid>/*.mp4  +  PostgreSQL (recordings, kept)
        
Go API (cmd/api) ── REST /api/v1 ──► React SPA (web/)
   ├── монитор доступности камер (MediaMTX paths, 10 c)
   ├── воркеры детекции движения (ONVIF PullPoint)
   └── сканер записей и задач клипов (30 c)
```

## Структура

- `cmd/` — исполняемые приложения (`cmd/api` — HTTP API и фоновые воркеры);
- `internal/` — прикладной код Go:
  - `internal/auth` — argon2id и JWT;
  - `internal/config` — конфигурация из переменных окружения;
  - `internal/discovery` — WS-Discovery сканер сети;
  - `internal/domain` — доменные модели;
  - `internal/http` — HTTP-обработчики, middleware, RBAC;
  - `internal/mediamtx` — клиент API MediaMTX;
  - `internal/monitor` — мониторинг доступности камер;
  - `internal/motion` — детекция движения по событиям ONVIF;
  - `internal/onvif` — ONVIF-клиент (профили, stream URI, события);
  - `internal/clipper` — кадрирование клипов через FFmpeg (Docker);
  - `internal/postgres` — репозитории (pgx);
  - `internal/recorder` — сканер каталога записей, ротация буфера, задачи клипов;
- `migrations/` — миграции базы данных (goose):
  - `00001` — базовая схема (cameras, recordings, events, users);
  - `00003` — ONVIF-поля камер;
  - `00004` — режимы записи, флаг `kept`;
  - `00005` — очередь задач кадрирования `clip_jobs`;
- `web/` — фронтенд на React + TypeScript (Vite);
- `deployments/` — Docker и инфраструктурные файлы (PostgreSQL, MediaMTX);
- `scripts/` — вспомогательные скрипты (`migrate.sh`, `api-run.sh`, `db-psql.sh`);
- `storage/` — локальное хранилище медиафайлов для разработки
  (`storage/recordings/…` — сегменты MediaMTX, `storage/clips/…` — клипы движения).

## Быстрый старт

1. Требования: Go 1.22+, Node.js 18+, Docker, (опционально) образ FFmpeg:

   ```bash
   docker pull jrottenberg/ffmpeg:latest
   ```

2. Инфраструктура (PostgreSQL, MediaMTX):

   ```bash
   cd deployments
   docker compose up -d
   ```

3. Конфигурация: скопировать `.env.example` в `.env`, задать `DATABASE_URL`, секреты JWT и администратора.

4. Миграции и запуск API:

   ```bash
   ./scripts/migrate.sh up
   ./scripts/api-run.sh
   ```

5. Фронтенд:

   ```bash
   cd web
   npm install
   npm run dev
   ```

6. Вход: `ADMIN_USERNAME` / `ADMIN_PASSWORD` (по умолчанию `admin` / `admin123`).

## Эксплуатационные заметки

- **Сегменты и клипы.** Сегменты MediaMTX — 5 минут; клипы движения вырезаются после закрытия сегмента, поэтому клип появляется в архиве не позднее ~5 минут после эпизода. До готовности клипа кнопка «Просмотр» показывает покрывающий сегмент.
- **ONVIF.** Для детекции движения и сканера на камере должен быть включён ONVIF и создан ONVIF-пользователь; порт службы указывается в настройках камеры (часто 80 или 8899).
- **Брандмауэр.** WS-Discovery использует UDP-multicast: при первом запуске API разрешите сетевой доступ приложению Go в брандмауэре Windows.
- **Секреты.** RTSP-URL и учётные данные ONVIF хранятся в базе в открытом виде (внутренняя система за NAT); перед продакшеном запланировано шифрование.
- **Производительность монитора.** Для видеостены на 12–18 ячеек рекомендуется добавлять камеры суб-потоком (меньшее разрешение/H.264).

## Дорожная карта

- Интеграция с пожарной безопасностью: справочник пожарных зон, привязка камер, приём внешних тревог, тревожная подсветка зон на мониторе (Шаг 13).
- Перевод сессии на `httpOnly`-cookie с защитой CSRF.
- Шифрование секретов камер в базе данных.
- Программный детектор движения для RTSP-камер без ONVIF.
- Точная обрезка клипов без перекодирования (smart cut по keyframe + edit list).
